CONCEPTION & ARCHITECTURE — Vue globale (1/2)

TER_S1_N/ ├── src/ │ ├── config/ # Connexion MongoDB, secrets │ ├── models/ # Maze.js (schéma + validations) │ ├── controllers/ # generationController, statsController │ ├── routes/ # mazeRoutes.js, statsRoutes.js │ └── services/ │ ├── pythonBridge.js │ └── mazeGeneration/ (Python) └── test/ # maze_tester, scénarios API

MVC Express découple les responsabilités : routes minimalistes, contrôleurs focalisés sur la logique métier, services spécialisés (bridge, génération, métriques). Cette modularité a permis les refactorings rapides et le passage en production sans dette majeure.

CONCEPTION & ARCHITECTURE — Implémentation (2/2)

Models

Schéma `Maze` : dimensions, matrice, métriques, tags, timestamps. Validation côté DB pour éviter données incomplètes.

Controllers

`generationController` orchestre validation → bridge → tests → persistance. Logs structurés pour traçabilité.

Services

`pythonBridge` encapsule `child_process.spawn`, timeouts, kill, parsing JSON, remontée d'erreurs.

REST API — Migration & robustesse

GET /api/generate?largeur=15&hauteur=10&save=true&name=pacmaz GET /api/mazes # liste (pagination WIP) GET /api/mazes/:id # détail + métriques DELETE /api/mazes/:id # suppression sécurisée GET /api/stats # volumes, moyennes, dernières notes


  • Migration prototype → Express: séparation routes/contrôleurs, middlewares, validation stricte.
  • Validation des requêtes: largeur/hauteur 3–50, `isNaN` + messages HTTP 400 dédiés.
  • Gestion erreurs Python: stderr capturé, code retour ≠0 → HTTP 500 documenté.

⚙️ SPÉCIFICATIONS TECHNIQUES — Bridge & debug

  • Bridge résilient: `child_process.spawn` + `AbortController` maison pour couper les scripts longs, récupération stdout/stderr tamponnée.
  • Gestion multi-threads/process: kill group (`process.kill(-pid)`) pour libérer Render et éviter facturation.
  • Debug : logs horodatés, niveaux (INFO/WARN/ERROR), reproduction locale via scripts.
  • Validation REST API: fuzz paramètres, injection de fautes, suivis Postman.

DÉPLOIEMENT — Render & infra

Render Web Service

Build Node 18 + Python 3.11, scripts `npm install` + `pip install`, start `node src/index.js`.

MongoDB Atlas

Cluster M0, whitelist IP Render, variables d'env (URI, DB_NAME).

Flux Git → Prod

Push main → GitHub Actions (tests) → Render (deploy hook) → expose HTTPS auto.

Infra nécessaire: 512 MB RAM Render (Free), 0.1 vCPU, quotas respectés (<5s CPU). Latence moyenne France → Render (US/EU) ≈ 200 ms.
